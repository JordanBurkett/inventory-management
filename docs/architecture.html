Factory Inventory Management System

Architecture overview: system layout, tech stack, and data flow

System Architecture

A two-tier application. A Vue single-page app talks to a FastAPI service over REST. There is no database.

Versions are the declared minimums from client/package.json and server/pyproject.toml.

Data Flow

What happens when a user changes a filter on the dashboard.

  1. User changes a filter in FilterBar. It updates shared refs in useFilters, a module-level singleton.
  2. The view's watcher fires and calls getCurrentFilters(). Period is sent as month and location as warehouse.
  3. api.js builds a query string and omits any value equal to all, then sends the request with axios.
  4. The FastAPI route runs apply_filters (warehouse, category, status), then filter_by_month for orders.
  5. Results are validated against the Pydantic response_model and returned as JSON.
  6. The view stores raw data in refs; charts and totals are recomputed from computed() properties.

The four global filters

FilterQuery paramApplies to
Time PeriodmonthOrders, dashboard summary
WarehousewarehouseInventory, orders, summary

Inventory has no date field, so it ignores the period filter. month accepts either YYYY-MM or a quarter such as Q3-2025, matched by substring on order_date.

Things to Know

Gaps found while reading the code, useful before you build on it.

Client calls endpoints the server does not define.
  • api.js calls /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET), but main.py has no such routes. Those calls will return 404.
  • main.py defines PurchaseOrder and CreatePurchaseOrderRequest models but no route that uses them.
  • State is read-only in memory, so any future write endpoints would reset when the server restarts.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • The Backlog view file exists but is not registered as a route; backlog data is shown through the Dashboard.
